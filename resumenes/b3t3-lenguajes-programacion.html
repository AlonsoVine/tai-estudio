1 Lenguajes de programación

1.1 Definiciones básicas

AlgoritmoConjunto de acciones / secuencia de operaciones que, ejecutadas en un orden, resuelven un problema concreto. Secuencia ordenada de pasos sin ambigüedades, repetible. Hay n algoritmos por problema → escoger el más eficiente.
Características: preciso (orden de cada paso) · definido (repetido n veces → mismo resultado) · finito · independiente del lenguaje · describe 3 partes: Entrada, Proceso, Salida · programar = adaptar el algoritmo al ordenador · independiente de dónde se implemente (HW o SW).
InstrucciónCada tarea elemental a realizar por un elemento de computación.
ProgramaConjunto de instrucciones que al ejecutarse resuelven un problema. 3 partes: ① Entrada (instrucciones de lectura: usuario o almacenamiento secundario) ② Acciones del algoritmo → declaración de variables + instrucciones ③ Salida (acciones de escritura: dispositivo o almac. secundario).
Lenguaje de programaciónConjunto de normas «lingüísticas» que permiten escribir un programa entendible por el ordenador y trasladable a ordenadores «similares».
SubprogramaFragmento que resuelve un subproblema con entidad propia. Permite reusabilidad y distribuye la programación (niveles de abstracción / equipo).
FunciónSubprograma con «n» entradas y una única salida (siempre una).
ProcedimientoSubprograma con «n» entradas y «n» salidas (n = {0, 2, … n} literal; ver incoherencias).
TraductorPrograma que procesa un texto fuente y genera un texto objeto. Según la forma: compiladores e intérpretes.

1.2 Compiladores

Compilador: traduce el código fuente a su equivalente en un lenguaje de más bajo nivel (código objeto) que la máquina pueda interpretar. Normalmente lenguaje máquina; también código intermedio (bytecode) o texto. El proceso = compilación.

TareaFases
Análisis
(corrección del fuente)		Léxico (scanner): fuente → tokens (secuencia de caracteres con significado propio) · Sintáctico (parser): agrupa tokens jerárquicamente en frases gramaticales en un árbol; expresiones, sentencias y asignaciones según las reglas · Semántico: validez (operandos permitidos para un operador, variables usadas no definidas, llamadas con nº/tipo de parámetros incorrecto)
Síntesis
(salida en lenguaje objeto)		Generación de código (intermedio u objeto) · Optimización de código

Proceso de compilación = 4 etapas: ① Preprocesado: interpreta directivas (#define → se sustituye por su valor) → ② Compilación: → ensamblador del procesador → ③ Ensamblado: ensamblador → código objeto (binario máquina) → ④ Enlazado: reúne módulos objeto + código de las bibliotecas.

⚠ «Compilación» es el proceso entero y también la 2ª etapa. El ensamblador lo produce la etapa de compilación; el código objeto, la de ensamblado.

TranspiladorFuente → otro lenguaje fuente distinto, mismo nivel de abstracción. TypeScript → JavaScript.

2 Representación de tipos de datos

Tipos de datos: definen el modo en que se usa el espacio (memoria); indican al compilador cómo crear y manipular el almacenamiento. Predefinidos (el compilador los comprende intrínsecamente) vs abstractos (definidos por el usuario como clase; el compilador lee la definición de la clase). Otros: struct, clases, tipos complejos en jerarquía.

Casting: transformar un valor de un tipo a otro. Normalmente: fuertemente tipados → implícitas y explícitas; débilmente tipados → solo implícitas.

4 Instrucciones condicionales

ifDecisión más simple: ejecuta el bloque si la condición (booleana) es true.
if-elseBloque alternativo si la condición es false.
if anidado (nested-if)if dentro de otro if o else; cadena else if.
switch-caseBifurcación de múltiples vías (selección múltiple) según el valor de la expresión; break por caso; default si no coincide ninguno.
switch (expr) { case valor1: decl1; break; … default: declDefault; }

⚠ Sin llaves, el if solo incluye la instrucción inmediatamente siguiente: en if(c) decl1; decl2; decl2 se ejecuta siempre.

✎ Ejemplo del tema: i=9 → no casa con 0, 1, 2 → default: «i es mayor que 2.»

5 Bucles y recursividad

Bucle: ejecuta un conjunto de instrucciones repetidamente mientras la condición sea verdadera.

BucleClaveMín.
while«if repetitivo». Comprueba antes = control de entrada. Pasos: condición → si false, fin → cuerpo → volver.0

for-eachRecorre colección o array de forma secuencial sin conocer el índice; inflexible. for (T e : coleccion)—

✎ Ejercicios del tema: x=2; x<=4; x++ → 3 · x=20; x<=30; ++x → 11 · x=10; x>1; --x → 9 · i=5; i!=0; i-=2 → 5, 3, 1, -1… nunca vale 0 → bucle infinito ⚠. «¿Mínimo de un while?» → 0.

Recursividad: definir el problema en base a su propia definición. Subproblemas de la misma naturaleza y menor tamaño → técnica divide y vencerás. Obligatorio un caso base o de parada (solución inmediata).

int facR(int n){ if(n==0) return 1; return facR(n-1)*n; }
int potencia(int x,int n){ if(n==0) return 1; else return x*potencia(x,n-1); }

Otros ejemplos del tema: facI (factorial iterativo con for), cuentaNodos (árbol binario: 1 + nodos izq + nodos dcha).
Inconvenientes: más lenta que la iterativa (sobrecarga de llamadas) · demasiadas llamadas → desbordamiento de pila (stack overflow).

✎ Ejercicios del tema: (a) t=true; println("Antes de return."); if(t) return; println("Salida."); → se ejecutan 4 instrucciones (declaración, println, if, return); «Salida.» nunca se imprime. 7 Vectores y registros

Array o vector: colección de variables del mismo tipo referenciadas por un nombre común; 1 o más dimensiones (el unidimensional es el más común = lista de variables relacionadas). Ventajas: manipulación y ordenación fáciles. En Java se implementan como objetos → los no utilizados pueden ser recolectados.

Declarartipo nombre[]; o tipo[] nombre; → 2 componentes: tipo (de los elementos; primitivo o clase) y nombre. Solo crea la referencia.
Crearnombre = new tipo[tamaño]; · combinado: int[] a = new int[20]; · 2 pasos (declarar + new) → todos los arrays se asignan dinámicamente.
Valores iniciales0 numéricos · false boolean · null referencias.
AccesoPor índice: de 0 a tamaño − 1; recorrido con for(int i=0; i<arr.length; i++)
MultidimensionalMatrices = arrays de arrays; un [] por dimensión: int[][] m = new int[10][20]; (2D) · new int[10][20][10] (3D)
RegistrosEl tema se remite a temas anteriores (sin contenido aquí).

8 Estructura de un programa

Entrada de datosSuministra los datos necesarios: usuario, periférico, BBDD u otras fuentes, otras aplicaciones, sensores…
ProcesamientoEl corazón del programa: el código que procesa los datos (incluidos los de entrada).
Salida de datosResultado guardado en BBDD, enviado a periférico de salida, a un actuador, a otro programa o mostrado por pantalla.

⚠ Tres tríadas parecidas: algoritmo (Entrada · Proceso · Salida) · programa en 1.1 (Entrada · Acciones del algoritmo · Salida) · apartado 8 (Entrada · Procesamiento · Salida).

Incoherencias del material

  1. Procedimiento «n = {0, 2, … n}» (tema, 1.1): omite el 1; error evidente → n = {0, 1, 2, … n}. El repaso solo dice «n entradas y n salidas».
  2. Java: la tabla de lenguajes del tema lo marca «Compilado»; el apartado (4) Traducción y el repaso lo dan como mixto (bytecode + máquina virtual). Si preguntan por tipo de traducción: mixto.
  3. Conversión implícita (tema y repaso): el esquema double ← float · long ← int ← short ← byte es incompleto para Java. La especificación define 19 ampliaciones, entre ellas long → float/double, int → float/double y char → int/long/float/double (JLS §5.1.2, docs.oracle.com/javase/specs). Para el examen, el esquema del tema; no descartar opciones que incluyan esas otras.
  4. boolean = 8 bits: así lo dan tema y repaso. ✎ Aviso propio no verificado con búsqueda: la especificación de Java no fija el tamaño de boolean. Para el examen, 8 bits.
  5. Ejercicio for sin llaves (tema, p. de return): en Java no compila (una declaración no puede ser el cuerpo único del bucle y j queda fuera de ámbito en el if).
