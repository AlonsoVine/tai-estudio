1. Estándar ANSI/ISO SQL

2. DDL — definición

Tipos: CHAR(n) VARCHAR(n) BIT BIT VARYING NUMERIC DECIMAL INTEGER SMALLINT REAL FLOAT(p) DOUBLE PRECISION DATE TIME TIMESTAMP

Esquema

El estándar no tiene «crear BD»; usa esquema:

CREATE SCHEMA {<nombre> | AUTHORIZATION <usuario>} [<elementos>]; DROP SCHEMA <nombre> {RESTRICT|CASCADE};

RESTRICT: solo si está vacío · CASCADE: siempre.

Tabla

CREATE TABLE t ( col VARCHAR(50) DEFAULT {literal|función|NULL} NOT NULL, PRIMARY KEY (col), FOREIGN KEY (fk) REFERENCES t2(pk) ON DELETE {NO ACTION|CASCADE|SET DEFAULT|SET NULL} ON UPDATE {…mismas opciones…}, CONSTRAINT n CHECK (cond) );
  • UNIQUE: sin repetidos (clave candidata). PRIMARY KEY: sin repetidos ni nulos. Existen a nivel de columna y de tabla (varias columnas).
  • REFERENCES = clave foránea.

Aserción (restricción global, varias tablas)

CREATE ASSERTION n CHECK (cond); DROP ASSERTION n;

Modificar y borrar tabla

ALTER TABLE t { ADD [COLUMN] col def | ALTER [COLUMN] col {SET DEFAULT x | DROP DEFAULT} | DROP [COLUMN] col {RESTRICT|CASCADE} | ADD restricción | DROP CONSTRAINT n {RESTRICT|CASCADE} }; DROP TABLE t {RESTRICT|CASCADE};

RESTRICT: no borra si hay dependencias · CASCADE: borra lo que la referencie.

Vista (tabla virtual, no materializada; esquema externo)

CREATE VIEW v [cols] AS (consulta) [WITH CHECK OPTION]; DROP VIEW v {RESTRICT|CASCADE};
  • Actualizable solo si procede de una tabla sin GROUP BY/HAVING.
  • WITH CHECK OPTION: solo admite inserciones/modificaciones que cumplan la consulta de la vista.
  • Ventajas: seguridad y legibilidad.

Dominio

CREATE DOMAIN d [AS] tipo [DEFAULT …] [CONSTRAINT n CHECK (VALUE IN (…))]; ALTER DOMAIN d {SET DEFAULT|DROP DEFAULT|ADD CONSTRAINT …|DROP CONSTRAINT n}; DROP DOMAIN d {RESTRICT|CASCADE};

Dominio: RESTRICT solo si no se usa; CASCADE lo borra y deja su tipo base.

Índice y TRUNCATE

CREATE [UNIQUE] INDEX i ON t(c1,c2); DROP INDEX i; TRUNCATE TABLE t;

DELETE borra filas (DML, admite WHERE) · TRUNCATE vacía la tabla y resetea contadores (DDL) · DROP elimina la tabla.

3. DML — manipulación y consulta

INSERT INTO t [(cols)] {VALUES (v|DEFAULT|NULL,…) | consulta}; UPDATE t SET col = {expr|DEFAULT|NULL}[,…] [WHERE cond]; DELETE FROM t [WHERE cond]; -- sin WHERE: todas las filas

SELECT

SELECT [ALL|DISTINCT] cols|* FROM tablas [WHERE c] [GROUP BY cols] [HAVING c_grupo] [ORDER BY col [DESC]];
  • Álgebra relacional: SELECT = proyección π · WHERE = selección σ · FROM = producto cartesiano ×.
  • AS = alias. ALL es el valor por defecto. ORDER BY: ASC por defecto; columnas ya presentes en SELECT.
  • Operadores: < <= > >= = != · AND OR NOT. Precedencia: comparación → NOT → AND → OR (paréntesis para forzar).
  • BETWEEN a AND b (intervalo cerrado) · LIKE (% 0..n caracteres, _ 1 carácter) · IN · IS [NOT] NULL. Todos admiten NOT.
  • CASE simple CASE expr WHEN v THEN r … ELSE r END o de búsqueda CASE WHEN cond THEN r …. Sin ELSE ni coincidencia → NULL.
  • Agregación: COUNT SUM MIN MAX AVG. COUNT(*) filas · COUNT(col) no nulos · COUNT(DISTINCT col) no nulos y distintos.
  • WHERE filtra filas (antes de agrupar) · HAVING filtra grupos. En SELECT con GROUP BY: solo columnas del GROUP BY + agregados.
  • Subconsultas (en WHERE/HAVING): ANY (alguno) · ALL (todos) · [NOT] EXISTS (¿devuelve algo?).

JOINs

  • CROSS JOIN (o FROM t1, t2 sin condición): producto cartesiano.
  • Combinación: FROM t1, t2 WHERE t1.k = t2.k o JOIN … ON cond | USING(col). SELF JOIN: la tabla consigo misma.
  • NATURAL JOIN: automático por columnas de igual nombre, elimina la duplicada (caso de INNER).
  • INNER JOIN: solo coincidentes; hay que indicar ON/USING.
  • LEFT | RIGHT | FULL [OUTER] JOIN: conservan todo lo de la izquierda / derecha / ambas, con NULL sin pareja.
  • Más de 2 tablas: (t1 JOIN t2 ON …) JOIN t3 ON …

Operaciones de conjuntos

Columnas con dominios compatibles. UNION [ALL] unión · INTERSECT [ALL] en ambas · EXCEPT [ALL] en la 1.ª y no en la 2.ª. Con ALL mantienen repetidas.

4. DCL — control

  • Transacción: unidad lógica de trabajo (todo o nada). Inicio implícito (CREATE, ALTER, INSERT, UPDATE…) o explícito SET TRANSACTION. Fin explícito:
  • COMMIT confirma · ROLLBACK deshace hasta el inicio · SAVEPOINT punto intermedio al que volver con ROLLBACK.
GRANT privilegios ON objeto TO usuarios [WITH GRANT OPTION]; REVOKE [GRANT OPTION FOR] privilegios ON objeto FROM usuarios;
  • Privilegios: ALL PRIVILEGES, USAGE, SELECT, INSERT, UPDATE, DELETE. Objetos: DOMAIN, TABLE, VIEW. Usuarios: lista o PUBLIC.
  • WITH GRANT OPTION: el receptor puede conceder a su vez esos privilegios.

5. Procedimientos almacenados

Programa guardado y ejecutado dentro del SGBD: acceso directo a datos y solo devuelve el resultado (eficiencia). Usos: validar datos, encapsular procesos complejos o costosos, lógica de negocio. La implementación varía por gestor.

6. Eventos y disparadores (triggers)

Procedimiento almacenado que se ejecuta automáticamente ante INSERT, UPDATE o DELETE, sin intervención del usuario. Usos: reglas de negocio, campos calculados, históricos/logs, restricciones, relaciones exclusivas.

  • Temporalidad: BEFORE / AFTER el evento, o INSTEAD OF (sustituye la sentencia; útil en vistas).
  • Granularidad: FOR EACH ROW (una vez por fila) / FOR EACH STATEMENT (una vez por sentencia). UPDATE OF col1, col2 solo en nivel de fila.
  • Condición: WHEN (…) solo en nivel de fila. :OLD = valor antiguo (sin sentido en INSERT) · :NEW = nuevo (sin valor en DELETE).
  • Acción: BEGIN … END;
CREATE OR REPLACE TRIGGER actualizar AFTER UPDATE OF A, B ON tabla FOR EACH ROW BEGIN INSERT INTO log (A, B) VALUES (:new.A, :new.B); END actualizar;

DriverUno ODBC por cada SGBDEl fabricante aporta el suyo; se instala donde corre la app

4 tipos de driver JDBC:

  • Tipo 1 · Puente JDBC-ODBC: traduce a ODBC (driver ODBC en el cliente). Acceso a casi todo, pero ineficiente.
  • Tipo 2 · API nativa: traduce a la API propia del SGBD. Más eficiente que el 1; ligado al SGBD; se instala en cada cliente.
  • Tipo 3 · Middleware: protocolo independiente hacia un servidor intermedio. Un driver vale para varias BD; añade un nivel y baja el rendimiento.
  • Tipo 4 · Java puro (thin): 100 % Java, habla directo el protocolo del SGBD. Muy eficiente; ligado al SGBD.

Flujo JDBC: DriverManager.getConnection(url,user,pass) → createStatement() → executeQuery() → ResultSet.

Incoherencias del material (para el examen manda el tema):
  • Repaso: última norma ISO/IEC 9075:2016; tema: 2023. Vale 2023.
  • El tema describe NUMERIC/INT como «decimal»: INT es entero.
  • El tema pone DELETE FROM empleados como «eliminar la tabla»: solo borra las filas; la tabla se elimina con DROP TABLE.
  • Muchos textos llaman TCL a COMMIT/ROLLBACK/SAVEPOINT; el tema los incluye en DCL, y TRUNCATE en DDL.
  • En la práctica, casi ningún SGBD implementa CREATE ASSERTION, y OR REPLACE en procedimientos MySQL no existe en MySQL puro (sí en MariaDB).
